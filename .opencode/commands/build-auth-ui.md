Load the build-auth-ui skill and execute it.

Create Authentication UI for CompanySystem using the existing backend.

Read:

- CompanySystem.Web/Controllers/AuthController.cs
- CompanySystem.Business/DTOs/LoginDto
- CompanySystem.Business/DTOs/RegisterDto
- CompanySystem.Business/DTOs/Auth related DTOs

Create if missing:

- CompanySystem.Web/Views/Auth/Login.cshtml
- CompanySystem.Web/Views/Auth/Register.cshtml
- CompanySystem.Web/Views/Auth/AccessDenied.cshtml

Create or update:

- CompanySystem.Web/wwwroot/js/auth.js

Update only if needed:

- CompanySystem.Web/Views/Shared/_Layout.cshtml

Tasks:

1. Build Login page

Use:

POST /api/Auth/Login

with AJAX JSON request.

Store:

- accessToken
- refreshToken

after successful login.


2. Build Register page

Use:

POST /api/Auth/Register

with AJAX JSON request.

Register requires Admin authentication.

Send JWT Authorization header.


3. Build Logout functionality

Use:

POST /api/Auth/Logout

Remove:

- accessToken
- refreshToken
- current user data


4. Create authentication JavaScript helper

auth.js must:

- store tokens
- read tokens
- remove tokens
- decode JWT
- extract user role
- expose:

window.currentUser

window.currentUserRole


5. Configure AJAX authorization

Automatically attach:

Authorization: Bearer token

to protected requests.


6. Support build-ui integration

CRUD pages generated by build-ui depend on:

window.currentUserRole

for role based buttons.


Security rules:

DO NOT modify:

- AuthController
- Controllers authorization attributes
- Services
- Interfaces
- DTOs
- Entities
- Repositories
- DbContext
- Migrations
- Program.cs
- appsettings.json


NEVER remove:

[Authorize]

[Authorize(Roles="...")]


NEVER add or reduce permissions.


Backend security is the source of truth.


Follow the build-auth-ui skill instructions exactly.

Run:

dotnet build

Final result must be:

0 errors
